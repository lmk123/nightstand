# 设计说明与已知限制

这份文档写给开发者：功能的具体行为、加密设计、权限、网站图标和已知限制。面向普通用户的介绍在 [README](../README.zh-CN.md)，那里只写一句话简介、亮点和“能防住什么”。

## 功能行为

- **收藏列表**：添加当前标签页或手动输入网址；支持搜索、编辑、删除。为了防止误点，单击一行只会选中它，要点这一行的“打开”按钮或按回车才会打开；搜索时第一条结果自动选中，可以用 ↑↓ 切换。每个条目可以选择清理范围：
  - **整个站点**（默认）：只看域名，包括所有子域名；路径、协议、端口都不管。
  - **仅此网址**：只匹配这一个地址。协议、开头的 `www.`、`#` 之后的部分和末尾的斜杠不影响匹配，`?` 之后的参数必须完全一致。同一网站的其他页面会留在历史里。
  - **附加域名**：每个条目还可以填几个其他域名，按“整个站点”处理（含所有子域名），和条目本身选哪种范围无关。适合网站会跳去的其他域名，比如付款页、播放视频用的域名（如 `video.twimg.com`）：保存时、以后每次访问时，它们的记录和书签会和条目本身一起删除。列表里条目后面的“+N”表示有 N 个附加域名。
  - 表单里的“两种范围有什么区别？”和“附加域名是什么？怎么找？”会打开弹窗内的常见问题。
- **自动清理浏览记录**
  - 访问受保护站点后立即删除，同一站点的其他记录（重定向、子页面）也一并删除。
  - 新增条目时，立刻清理该站点已有的历史。
  - 浏览器启动时做一次全量扫描，之后每 15 分钟做一次增量扫描。
  - 锁定状态下照样会清理（靠下面的哈希匹配表）。
- **伪装界面**：锁定时显示一个普通的快捷链接启动器，默认链接是 GitHub、MDN、Google Docs、Gmail，可以自定义。在“筛选…”框里输入口令后按回车即可解锁。口令输错时没有任何提示。
- **关闭即上锁**：解锁状态只存在于弹窗的内存里。弹窗一关就锁上，没有“保持解锁 N 分钟”之类的选项。
- **快速收起**（代码里叫 panic）：默认快捷键 `Alt+Shift+Q`（Mac 上是 ⌥⇧Q）。关闭受保护站点的标签页和 Nightstand 打开的无痕窗口，立即清理历史，并关闭弹窗。
- **遮住与静音**（设置里两个开关，默认都开）：打开受保护的网页时，页面先被一层不透明的遮罩盖住，标签页标题换成“新标签页”，标签页静音；点遮罩中间的“显示页面”才显示内容并恢复声音。
  - 显示之后，在同一个标签页里继续点受保护站点内的链接，新页面保持显示；离开受保护站点再回来，重新遮住。
  - 以下情况会重新遮住并静音：切换到别的标签页（或最小化窗口）、浏览器窗口失去焦点（切到别的应用或别的浏览器窗口）、这个页面里 60 秒没有键盘鼠标操作（看视频时也照常计时）。
  - 静音不依赖遮罩：后台标签页里的受保护网页突然开始播放，也是静音的。Nightstand 只撤销自己设的静音，用户自己点的静音不动。关掉“自动静音”时，撤销所有由 Nightstand 设的静音。
  - 实现：一个网页脚本（`content/cover.ts`）在所有 http/https 网页的顶层框架里、`document_start` 时运行。它先用 `html{opacity:0}` 把整页藏起来，查完匹配表再决定：不受保护就立即撤掉，受保护就盖上遮罩（顶层的 popover，宿主元素带封闭的 shadow root）。查表在 https 页面上由脚本自己算哈希；纯 http 页面不是安全上下文，没有 `crypto.subtle`，改为问后台（后台用发消息的框架网址匹配）。后台在 `storage.session` 里按标签页 id 记录“已遮住 / 已显示”，只记 id，不记网址。
  - 两个开关存在明文的 `prefs` 里（不在加密列表里），因为锁定时网页脚本和后台也要读。
- **三种打开方式**：当前标签页、新标签页、无痕窗口（Firefox 上是隐私窗口）。无痕窗口需要先在扩展详情页允许 Nightstand 在无痕模式下运行。
- **书签**：保存条目时一并删除指向这个站点（或网址）的书签；也可以从书签批量导入，可选择导入后删除原书签。
- **保存前确认**：保存前列出马上要删除的内容（多少个网页的浏览记录、多少个书签），确认后才保存。可以勾选“不再提示”（`skipSaveNotice`），之后在设置里重新打开。
- **保存后自查**：新增条目、或者改了网址 / 清理范围 / 附加域名之后，列表顶部提示用户新开标签页在地址栏里试一试；还能看到这个网站，通常是网站跳去了别的域名，应加进“附加域名”。
- **常见问题**：解锁后“设置”里的一个视图，解释两种清理范围、附加域名以及数据怎么保存、能否被破解。不会打开新标签页。
- **备份与恢复**：导出加密的 `.nightstand` 备份，用当时的口令或恢复码导入，导入时和现有条目合并去重；也可以导出明文列表，导出前有醒目警告。
- **口令**：至少 4 个字符，不评价强弱。可以修改口令、重新生成恢复码。忘记口令时，在筛选框里粘贴恢复码再按回车，即可设置新口令。设置引导建议用几个互不相关、看起来像普通筛选词的词。
- **外观**：工具栏图标可以在床头柜、书本、星形、网格之间切换（只能在解锁后的设置里改）。扩展管理页上的名称和描述是中性的：Nightstand，“把常用链接放在手边”（英文 “Keep your everyday links close at hand”）。
- **语言**：英文（`en`，默认）和简体中文（`zh_CN`）。浏览器语言是简体中文时显示中文，其他语言（包括繁体中文）都显示英文。

## 加密设计

- 整个收藏列表用随机生成的数据密钥（AES-256-GCM）加密，存在 `storage.local` 里，**从不使用 `storage.sync`**。
- 数据密钥被包裹两份：
  - 一份用口令通过 PBKDF2-SHA256 派生的密钥包裹，迭代 600,000 次，随机盐；
  - 一份用恢复码派生的密钥包裹，恢复码含 160 bit 随机数。
- 解锁后，数据密钥只存在于弹窗页面的内存里，不写入任何存储，也不发给后台；弹窗关闭，密钥随之销毁。
- 只使用浏览器自带的 Web Crypto API，不引入第三方加密库。
- 存储格式和备份格式都带版本号。仓库里有一份固定的 v1 测试数据，以后每个版本都必须能解开它。列表内容（解密后的数据）目前是第 4 版：第 2 版加了附加域名，第 3 版去掉了备注和标签，第 4 版加了网站图标；读到旧版本时自动升级。

## 锁定状态下怎么清理：哈希匹配表

锁定时列表是解不开的，所以后台另外保存一份明文的“匹配表”：每个受保护的主机名（包括附加域名）或网址，加上本机随机生成的盐值，再做 SHA-256，只保存结果。

**这只能挡住随手翻看扩展存储的人。** 能读到匹配表和盐值的人，可以拿常见域名逐个算哈希来比对，从而还原出部分站点。README 的“防不住”一节用一句普通话说明了这一点。

## 权限

| 权限 | 用途 |
|---|---|
| `storage` | 保存加密的收藏列表、哈希匹配表和快捷链接设置（只用本地存储） |
| `history` | 删除受保护站点的浏览记录，这是核心功能 |
| `tabs` | 读取当前标签页的网址和标题以便添加；快速收起时找出并关闭受保护站点的标签页 |
| `alarms` | 定期做增量扫描 |
| `bookmarks` | 保存条目时统计并删除这个站点的书签；从书签导入 |
| `favicon`（仅 Chrome） | 从浏览器本地的图标缓存读取网站图标，显示在列表里 |
| 网页脚本，匹配所有 `http://*/*`、`https://*/*` | 遮住受保护的网页。事先不知道用户会收藏哪些网站，只能匹配所有网站；按站点申请权限反而会把受保护网站的域名写进扩展详情页的“网站访问权限”。安装时 Chrome 会提示“读取和更改您在所有网站上的数据” |

网页脚本只读取匹配表和 `prefs`，不读取网页内容（只读写标签页标题，以便遮住时换成中性标题、显示时还原），只给后台发“这个标签页已显示 / 已遮住 / 是否受保护”三种消息。整个扩展不发起任何网络请求，完全离线运行。网站图标也不例外：只读 Chrome 本地已缓存的图标，不会去网站上下载。

## 网站图标

- Chrome 删除一个网页的浏览记录时，会连同它缓存的图标一起删掉（已实测）。所以收藏条目的图标在**保存那一刻**（删除历史之前）截取一份 32×32 的 PNG，和条目一起加密保存。之前从没访问过、浏览器里没有图标缓存的网站，显示标题首字。
- 保存时没拿到图标的条目，之后访问一次这个网站，**下次解锁时**会再从本地缓存找一次，找到就存进去（弹窗在点开网站时就关闭了，所以只能等下次解锁）。这依赖一个时序：后台在访问被记录时就删掉历史，而图标通常要等网络下载完才写入缓存，晚于删除，于是能留下来（已实测）。如果图标先写入（例如已经在浏览器缓存里、瞬间加载），它会随历史一起被删，这次就找不到，下次访问再试。
- 也就是说，访问过的受保护网站，图标可能会留在 Chrome 的图标缓存文件里。它不会出现在地址栏、历史记录页或新标签页，只有直接读取浏览器数据文件才能看到，属于防护范围之外。
- 快捷链接是普通网站，历史不会被删，每次打开弹窗时直接读本地缓存；没有缓存就显示首字。
- Firefox 没有读取本地图标缓存的接口，一律显示首字。
- 明文导出不包含图标。

## 已知限制

| 事项 | 状态 |
|---|---|
| 访问后清理、锁定时清理、新增时清理已有历史、子域名匹配、`evil-example.com` 这类外观相似的域名不会被误删 | Chrome 已实测；Firefox 已用真实的 `places.sqlite` 验证后台清理 |
| Chrome 会把跳转链中间的网址（例如在地址栏输入域名后 http→https 的自动升级）记成 `history.search` 搜不到的记录，但地址栏仍会提示它们 | 清理时会按网址直接删除这些记录：每个被删网址的 http/https、带不带 `www.` 的写法，以及保存条目时该站点首页（或精确网址）的这些写法。跳到其他路径或其他域名的中间网址无法列举，所以删不到 |
| 网站用脚本跳转（`location.replace` 等，常见于登录、验证码、付款、刷新页面的流程）时，跳转前的那一页同样是 `history.search` 搜不到的记录，网址往往带随机参数（如 `/chat?c=…`），也可能在别的域名上 | 添加之后再访问：后台会收到这次访问并当场删除（Chrome 已实测）。添加之前留下的：Chrome 上删除每条记录时按访问时间删（`history.deleteRange`，窗口约 2 微秒），Chrome 会顺带删掉跳转到这次访问的整条跳转链，和在 `chrome://history` 里删除一样（已实测，包括从其他域名跳来的）。**删不到的情况**：跳转链的终点不在保护范围内（例如从受保护网站跳到另一个域名的付款页）——把那个域名也加进来，或在 `chrome://history` 里删掉终点那条；地址栏若仍提示，也可选中该提示按 Shift+Delete（Mac 上是 Shift+Fn+Delete）。Firefox 不做按时间删除（它只精确到毫秒） |
| 扩展自己的页面（弹窗）不会留在历史记录里 | Chrome 已实测（后台也会主动删除扩展自身页面的记录） |
| 新标签页“常去网站”：它由浏览历史生成，历史删除后理应随之消失 | 待手动确认 |
| 地址栏的**书签**提示：书签不受历史清理影响 | 保存条目时会删除这个站点的书签；之后新加的书签不会自动删除，再次保存该条目时会删除 |
| 地址栏的**已打开标签页**提示（“切换到这个标签页”）：标签页开着时无法避免 | 用快速收起关闭这些标签页 |
| 地址栏的**搜索联想**：由搜索引擎在服务端生成，和账户活动有关，扩展无法控制 | 不在防护范围内 |
| 地址栏的**快捷方式数据库**（曾经从地址栏选中过的条目）：Chrome 删除历史时理应一并清掉对应的快捷方式 | 待手动确认 |
| 开启 Chrome 同步时，`history.deleteUrl` 是否会同步删除其他设备上的记录 | 待手动确认；建议不要依赖这一点 |
| 扩展详情页（`chrome://extensions/?id=…`）有“在 Chrome 应用商店中查看”的链接，商店页面如实写着 Nightstand 的用途（商店政策要求详细说明与功能一致） | 不在防护范围内。名称、简介、图标仍是中性的；商店上架材料见 `apps/extension/store/` |
| 导出的备份文件名会出现在浏览器的下载记录里 | 文件名是中性的 `nightstand-日期.nightstand` |
| Firefox 上在弹窗里打开文件选择器通常会关掉弹窗，所以 Firefox 上导入备份改为粘贴文件内容 | Firefox 用粘贴，Chrome 用文件选择器（已实测弹窗不会关闭） |
| 遮住时，地址栏里的网址、标签页上的网站图标仍然可见 | 扩展改不了地址栏。图标不替换是有意的：替换后 Chrome 会缓存这个替代图标，收藏条目就再也取不到真正的图标 |
| 网页脚本进不去的页面不会被遮住：PDF、浏览器自带页面、应用商店页面、扩展安装或更新之前就已打开的标签页（重新加载后才有遮罩） | 这些标签页仍会被静音（浏览器启动、扩展安装时也会给已打开的受保护标签页静音） |
| 受保护网站的内容嵌在别的网站的 iframe 里 | 不遮住、不静音 |
| 网页脚本运行前到查表完成这段时间，页面一律不显示（`opacity:0`）；https 页面查表只需几毫秒，http 页面要等后台回答 | 首次绘制之前就应盖上遮罩，待手动确认（e2e 只检查遮罩、标题、静音的最终状态） |
| 页面在遮住期间打开自己的对话框、popover 或全屏 | 遮罩会重新提到最上层，全屏会被退出 |
| “60 秒无操作”只统计这个页面本身的输入；在嵌入的 iframe 里操作（例如别处嵌入的视频播放器）不算 | 有意保持简单 |
| 浏览器窗口失去焦点：打开 Nightstand 弹窗或开发者工具在某些系统上也可能算作失去焦点 | 待手动确认 |
| Firefox 上的遮罩和静音 | 待手动确认（Firefox 的 e2e 目前只检查后台的历史清理） |
| 输错口令没有次数限制，也没有延迟 | 有意为之：限流同样会挡住主人自己（在筛选框里多按几次回车后，正确口令也会被静默忽略），而旁观者手动猜口令时它帮助不大。防猜测只靠口令强度和 PBKDF2 |

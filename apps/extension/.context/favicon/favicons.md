# 网站图标

文中“已实测”的结论，日期和测法：未记录。

- Chrome 删除一个网页的浏览记录时，会连同它缓存的图标一起删掉（已实测）。所以收藏条目的图标在**保存那一刻**（删除历史之前）截取一份 32×32 的 PNG，和条目一起加密保存。之前从没访问过、浏览器里没有图标缓存的网站，显示标题首字。
- 保存时没拿到图标的条目，之后访问一次这个网站，**下次解锁时**会再从本地缓存找一次，找到就存进去（弹窗在点开网站时就关闭了，所以只能等下次解锁）。这依赖一个时序：后台在访问被记录时就删掉历史，而图标通常要等网络下载完才写入缓存，晚于删除，于是能留下来（已实测）。如果图标先写入（例如已经在浏览器缓存里、瞬间加载），它会随历史一起被删，这次就找不到，下次访问再试。e2e 因此故意让测试图标延迟返回（`e2e/favicon.e2e.ts`）。
- 快捷链接是普通网站，历史不会被删，每次打开弹窗时直接读本地缓存；没有缓存就显示首字。
- Firefox 没有读取本地图标缓存的接口，一律显示首字。
- 明文导出不包含图标。

## 已知限制

- 访问过的受保护网站，图标可能会留在 Chrome 的图标缓存文件里。它不会出现在地址栏、历史记录页或新标签页，只有直接读取浏览器数据文件才能看到，属于防护范围之外。
- 遮住页面时不替换标签页上的网站图标：替换后 Chrome 会缓存这个替代图标，收藏条目就再也取不到真正的图标（见 `apps/extension/.context/cover/cover-behavior.md`）。

# 遮住与静音：行为与已知限制

文中“已实测”“实测”的结论，日期和测法：未记录。

## 行为

- **遮住与静音**（设置里两个开关，默认都开，外加一个无操作时长）：打开受保护的网页时，页面先被一层不透明的遮罩盖住，标签页标题换成“新标签页”，标签页静音；点遮罩中间的“显示页面”才显示内容并恢复声音。按钮左侧是当前的工具栏图标（和伪装设置里选的一致），鼠标悬停时提示“Nightstand 暂时遮住了这个页面”，让用户认出是谁遮住的；旁观者只看到一个普通按钮。图标以 SVG 形状写在网页脚本里（`content/cover-icons.ts`，`lint` 里的 `tools/check-cover-icons.mjs` 检查它和 `icons-src/*.svg` 一致），用 `createElementNS` 画出来：不需要 `web_accessible_resources`（那会让网页能探测到扩展），也不经过 HTML 解析（开了 Trusted Types 的网页会拒绝 `innerHTML`）。只有真正遮住时才读取图标选择（不放在每个网页加载时都要等的那次读取里；从已显示的网页点进来、直接显示的网页不读）；读取失败时按钮只显示文字，下次遮住时再读。
  - 显示之后，在同一个标签页里继续点受保护站点内的链接，新页面保持显示；离开受保护站点再回来，重新遮住。用鼠标点后退、前进、刷新或地址栏时，鼠标已经移出网页，页面先被遮住，下一个页面也是遮住的（用键盘后退、刷新则保持显示）。
  - 以下情况会重新遮住并静音：鼠标移出网页（越过网页的边缘，去点标签栏、地址栏、窗口按钮或别的窗口）、切换到别的标签页（或最小化窗口）、浏览器窗口失去焦点（切到别的应用或别的浏览器窗口）、这个页面里一段时间没有键盘鼠标操作。
  - 无操作的时长在设置里选：1 分钟（默认）、2 分钟或 5 分钟，存在明文 `prefs` 的 `idleMinutes` 里；改了之后已显示的页面立即按新时长、从上次操作算起。标签页正在发出声音时（看视频、听音频）不会因为无操作而遮住：时间到了之后，网页脚本问后台这个标签页的 `tabs.Tab.audible`；正在播放的话，后台在 `tabs.onUpdated` 里看到 `audible` 变成 false 时通知网页脚本；网页脚本再等 10 秒的宽限期后重新问一次，仍然没有声音、这期间又没有操作的话就遮住。Chrome 的 `audible` 在任何约 2 秒的静音之后都会变成 false，不只是暂停、播完：缓冲、电影里的静默镜头、两首歌之间的间隙也会，宽限期就是为了不在这些时候遮住。所以停止播放后大约 12 秒遮住。不轮询：后台只在收到通知后被唤醒；万一通知没到（例如扩展刚更新），网页脚本每 10 分钟再问一次，长视频也不会每分钟唤醒一次后台。只改时长时，网页脚本直接从存储变化里取新值，不在每个打开的网页上重新匹配。`audible` 看的是整个标签页（包括 iframe 里嵌的播放器），被静音的标签页也算；没有声音的播放（网页里静音播放的视频、装饰性的循环背景视频）不算。没收到后台回答时按“不在播放”处理。
  - 鼠标移出就遮住，是为了赶在标签页被隐藏之前：标签页一隐藏，浏览器就不再给它绘制新画面，这时才盖上的遮罩进不了画面；切回来时 Chrome 先显示这个标签页隐藏前的最后一帧（也就是页面内容），等新画面画好才换成遮罩，于是页面会闪一下。网页脚本在隐藏之前收不到任何提示（实测没有 `blur`，也没有动画帧），能提前知道的只有鼠标离开。
  - 漏掉一次离开就会闪出页面内容，多遮一次只是多点一下，所以宁可多遮：只要可能是离开就遮住。算作离开的有：`mouseout` 的 `relatedTarget` 为空；在网页里按下的鼠标键在外面松开（`mouseup`；按着键拖出边缘时浏览器不发 `mouseout`（实测），松开后要等鼠标再动一下才补发，那时可能已经点了别的标签页）；拖着链接或文件离开窗口（`dragleave` 的 `relatedTarget` 为空，或 `dragend`）。都要求坐标落在网页可见范围的边缘或外面（松开鼠标键时要在边缘以外：窗口贴着屏幕边缘时，最边上那一像素的点击是在点滚动条、全屏播放器的控件，不是离开）：鼠标移到网页上方的菜单、下拉选项、浏览器气泡上时，指针仍在网页范围内，不算；按着鼠标键拖出边缘又拖回来松开，也不算。用触控板放大网页后，可见范围是视觉视口（`visualViewport`）那一块，而事件坐标相对于布局视口，所以按视觉视口的位置判断（实测）。这些监听只在页面显示时挂上。
  - 因此也会在这些时候遮住（有意接受）：右键菜单或下拉选项超出网页边缘，在边缘外选中一项之后；全屏看视频时鼠标碰到屏幕上沿（菜单栏、工具栏滑出）或移到另一块显示器，此时还会退出全屏；鼠标移到开发者工具、侧边栏等窗口里的其他区域；拖选文字时拖过边缘让页面滚动、拖视频进度条或滑块时，在窗口外松开鼠标键。
  - 静音跟着遮罩走：只在“先遮住页面”开着时生效（关掉遮罩后，页面不会再被“显示”，静音就永远解除不了，所以设置里的“自动静音”开关随之变灰）。后台标签页里的受保护网页突然开始播放，也是静音的。Nightstand 只撤销自己设的静音，用户自己点的静音不动（标签页已经静音时，Nightstand 不再静音一次，否则这个静音会被算成 Nightstand 的，显示页面时被撤销）。关掉“自动静音”或“先遮住页面”时，撤销所有由 Nightstand 设的静音；重新打开“自动静音”时，仍被遮住的标签页立即静音。关掉“先遮住页面”后再打开，已打开的标签页保持原样，下次加载时才遮住并静音（和新加入列表的网站一样）。
  - 把网站移出列表时，已打开的这个网站的标签页立即撤掉遮罩并取消静音；新加入列表的网站，已打开的标签页保持原样，下次加载（包括刷新）时才遮住并静音。
  - 实现：一个网页脚本（`content/cover.ts`）在所有 http/https 网页的顶层框架里、`document_start` 时运行。它先用 `html{opacity:0}` 把整页藏起来，查完匹配表再决定：不受保护就立即撤掉，受保护就盖上遮罩（用 `showModal()` 打开的 `<dialog>`，里面一个带封闭 shadow root 的元素放按钮）。用模态对话框而不是 popover：页面自己打开模态对话框时，对话框以外的一切（popover 也算）都会变成 inert，“显示页面”就点不动了；遮罩自己是最上层的模态对话框时，页面反而整个 inert，键盘也碰不到遮罩下面的内容。Esc 会被拦下，浏览器硬要关掉时再重新打开。查表在 https 页面上由脚本自己算哈希；纯 http 页面不是安全上下文，没有 `crypto.subtle`，改为问后台（后台用发消息的框架网址匹配）。后台在 `storage.session` 里按标签页 id 记录“已遮住 / 已显示”，只记 id，不记网址。
  - 两个开关存在明文的 `prefs` 里（不在加密列表里），因为锁定时网页脚本和后台也要读。

## 已知限制

| 事项 | 状态 |
|---|---|
| 遮住时，地址栏里的网址、标签页上的网站图标仍然可见 | 扩展改不了地址栏。图标不替换是有意的：替换后 Chrome 会缓存这个替代图标，收藏条目就再也取不到真正的图标 |
| 网页脚本进不去的页面不会被遮住：PDF、浏览器自带页面、应用商店页面、扩展安装或更新之前就已打开的标签页（重新加载后才有遮罩） | 这些标签页仍会被静音（浏览器启动、扩展安装时也会给已打开的受保护标签页静音）。扩展更新时不动已打开的标签页：旧的网页脚本已经联系不上后台，此时设的静音没法再用“显示页面”解除；更新前就被遮住静音的标签页，也要重新加载后点“显示页面”才能恢复声音；离开受保护站点时，Nightstand 设的静音也会撤销（更新清空了 `storage.session` 里的记录也一样） |
| 受保护网站的内容嵌在别的网站的 iframe 里 | 不遮住、不静音 |
| 网页脚本运行前到查表完成这段时间，页面一律不显示（`opacity:0`）；https 页面查表只需几毫秒，http 页面要等后台回答；后台没有回答（出错、预渲染等）时按受保护处理，保持遮住；预渲染的 http 页面在被打开时再问一次，不受保护就撤掉 | 首次绘制之前就应盖上遮罩，待手动确认（e2e 只检查遮罩、标题、静音的最终状态） |
| 页面在遮住期间打开自己的对话框、popover 或全屏 | 遮罩会重新提到最上层（重新 `showModal()`），全屏会被退出；页面的对话框留在遮罩下面（靠对话框的 `toggle` 事件，以及监听 `open` 属性兼顾不发这个事件的旧版浏览器） |
| 用键盘切换标签页（Ctrl+Tab、Cmd+数字等）或在触屏上用手指、触控笔点别的标签页后，再切回显示着的受保护页面，可能一瞬间看到切走前的页面，然后才是遮罩；鼠标从网页里嵌入的 iframe 直接移出窗口时也一样 | 浏览器行为：隐藏的标签页不再绘制，切回时先显示上一帧。用鼠标切换时，鼠标移出网页就已经遮住，不会闪；键盘切换和触屏点按在隐藏之前没有任何事件可用（触摸没有“移出”）；网页脚本只在顶层框架里运行，收不到 iframe 里的鼠标事件 |
| 鼠标移出时，浏览器给的坐标必须落在网页边缘或外面才算离开；有的平台（例如 Linux 的 Wayland 只告诉“离开了”，不带坐标）可能给的是离开前最后一个网页里的位置，这时不会遮住，切换标签页仍可能闪 | 待手动确认 |
| “无操作”只统计这个页面本身的输入；在嵌入的 iframe 里操作（例如别处嵌入的视频播放器）不算 | 有意保持简单；iframe 里的播放器发出声音时照样算在用 |
| 在网页里静音播放视频（只看画面、字幕）不算在用，时间到了照样遮住 | 有意为之：靠 `audible` 判断，才不会被页面上静音循环的背景视频一直挡住遮罩；需要时在设置里把时长调长 |
| 页面一直在发出声音（背景音乐、有声的自动播放广告、循环的提示音），或用户自己把标签页静音了但页面仍在播放，都算在用：只要声音不停，页面就一直不会因为无操作而遮住，没有时长上限 | 有意保持简单：`audible` 分不清这些声音是不是用户想听的；切换标签页、离开浏览器窗口照样会遮住 |
| 浏览器窗口失去焦点：打开 Nightstand 弹窗或开发者工具在某些系统上也可能算作失去焦点 | 待手动确认 |
| Firefox 上的遮罩和静音 | 待手动确认（Firefox 的 e2e 目前只检查后台的历史清理） |

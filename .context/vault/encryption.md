# 加密设计与哈希匹配表

## 加密设计

- 整个收藏列表用随机生成的数据密钥（AES-256-GCM）加密，存在 `storage.local` 里，**从不使用 `storage.sync`**。
- 数据密钥被包裹两份：
  - 一份用口令通过 PBKDF2-SHA256 派生的密钥包裹，迭代 600,000 次，随机盐；
  - 一份用恢复码派生的密钥包裹，恢复码含 160 bit 随机数。
- 解锁后，数据密钥只存在于弹窗页面的内存里，不写入任何存储，也不发给后台；弹窗关闭，密钥随之销毁。
- 只使用浏览器自带的 Web Crypto API，不引入第三方加密库。
- 存储格式和备份格式都带版本号。仓库里有一份固定的 v1 测试数据，以后每个版本都必须能解开它。列表内容（解密后的数据）各版本的变化见 `packages/core/src/model.ts` 里 `VaultData` 的注释；读到旧版本时自动升级。什么改动需要升版本号见 `packages/core/.claude/rules/storage/versioning.md`。

## 锁定状态下怎么清理：哈希匹配表

锁定时列表是解不开的，所以后台另外保存一份明文的“匹配表”（`index`）：每个受保护的主机名（包括附加域名）或网址，加上本机随机生成的盐值，再做 SHA-256，只保存结果（`packages/core/src/match-table.ts`）。

**这只能挡住随手翻看扩展存储的人。** 能读到匹配表和盐值的人，可以拿常见域名逐个算哈希来比对，从而还原出部分站点。README 的“防不住”一节用一句普通话说明了这一点。
